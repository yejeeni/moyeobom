# 모여봄 프로젝트 개요서

Oct 5, 2026 · @예진

## 프로젝트 개요

가상 스터디 메이트로 채워진 온라인 열람실에서, 할 일 단위로 집중하고 하루를 정산하는 PC 웹 서비스다.

| 항목 | 내용 |
| --- | --- |
| 서비스명 | 모여봄 |
| 한 줄 정의 | 혼자 공부해도 누군가와 함께 있는 느낌을 주는 가상 바디 더블링 열람실 |
| 형태 | PC 웹, 개인 취업용 포트폴리오 프로젝트 |
| 개발 방식 | 기간보다 완성도 우선, 단계별 확장 |

### 기획 배경

유튜브의 스터디윗미나 캠스터디처럼 다른 사람이 공부하는 모습을 틀어두면 집중이 잘 되는 현상을 바디 더블링이라고 한다. 하지만 캠스터디는 캠을 켜고 시간을 맞춰야 하는 부담이 있고, 영상은 내 공부 기록과 연결되지 않는다. 이 프로젝트는 실제 사람이 없어도 함께 공부하는 분위기를 만들고, 그 시간을 할 일 관리와 연결하는 데서 출발했다.

## 문제 정의와 목표

집중이 어려운 사람은 시작이 어렵고, 계획한 시간과 실제 걸린 시간의 차이를 잘 인식하지 못한다.

### 해결하려는 문제

- **혼자서는 시작이 안 된다**: 옆에 누군가 있어야 공부를 시작하고 유지할 수 있다.
- **함께하기엔 부담스럽다**: 캠스터디는 얼굴 공개, 시간 약속, 타인의 시선이 부담이다.
- **시간 감각이 흐리다**: 할 일에 시간이 얼마나 걸릴지 예측하기 어렵고, 예측이 틀려도 돌아보지 않는다.

### 목표

1. 접속만 하면 언제든 북적이는 열람실 분위기를 제공한다.
2. 오늘 할 일을 최소 하나 정하고 시작하게 해서 시작 장벽을 낮춘다.
3. 할 일별 예상 시간과 실제 시간을 기록하고 매일 정산해, 스스로의 시간 감각을 보정하게 돕는다.

## 타깃 사용자와 사용 상황

대상은 집중이 어려운 누구나이며, 홍보 키워드는 "ADHD를 위한 온라인 바디 더블링"으로 잡는다.

| 사용자 | 상황 | 기대하는 것 |
| --- | --- | --- |
| ADHD 성향의 사람 | 혼자서는 과제나 업무를 시작하지 못함 | 누군가 함께 있다는 느낌, 작게 쪼갠 할 일 |
| 대학생·취업 준비생 | 집이나 자취방에서 혼자 공부 | 도서관 같은 분위기, 공부 시간 기록 |
| 재택근무자 | 집에서 업무 집중이 어려움 | 사무실 같은 긴장감, 업무 시간 관리 |

주 사용 환경은 PC 웹이다. 공부나 업무 화면 옆에 작은 창으로 띄워두는 사용을 기본으로 가정한다.

홍보 시 "ADHD 치료", "증상 개선" 같은 의학적 표현은 쓰지 않고 "집중을 돕는 도구"로 표현한다.

## 핵심 컨셉

열람실의 모든 자리는 같은 규칙으로 그려지기 때문에, 사용자는 옆자리가 실제 사람인지 가상 메이트인지 구분할 수 없다.

### 가상 스터디 메이트

서버가 만든 가상 유저가 집중, 휴식, 입장, 퇴장을 자연스럽게 반복하며 빈자리를 채운다. 사용자가 혼자 접속해도 열람실은 항상 북적인다. 서비스 초기에 사용자가 적어 방이 비어 보이는 문제를 구조적으로 해결한다.

### 구분 불가 설계

- **캐릭터**: 실제 유저와 가상 유저 모두 같은 그림체의 캐릭터로 표시한다.
- **닉네임**: 입장할 때마다 "졸린 수달", "조용한 연필"처럼 형용사와 명사를 조합한 랜덤 닉네임을 부여하고, 한 세션 동안 유지한다. 가상 유저도 같은 규칙으로 이름을 받는다.
- **자리 이어받기**: 실제 유저가 늘어나면 가상 유저가 자연스럽게 퇴장하고 그 자리를 실제 유저가 이어받는다. 실제 유저가 나가면 잠시 뒤 가상 유저로 다시 채운다.
- **내 칸**: 내 자리만 "나"로 표시하고 강조한다.

### 투명성 원칙

개별 자리가 진짜인지는 공개하지 않지만, 가상 메이트가 섞여 있다는 사실 자체는 소개 화면과 열람실 안내에 명시한다. 바디 더블링은 알고 있어도 효과가 있으므로 컨셉을 해치지 않으며, 사용자가 속았다고 느끼는 것을 막는다.

## 사용자 흐름

할 일 관리는 스프린트 방식으로 운영한다. 입장 전 계획을 세우면 스프린트가 시작되고, 사용자가 "오늘 마무리"를 누르면 회고와 함께 끝난다.

1. **접속**: 비회원은 브라우저에 저장된 고유 ID로 식별한다. 진행 중인 스프린트가 있으면 이어서 시작한다.
2. **스프린트 계획**: 오늘 할 일을 최소 1개 적는다. 예상 시간은 선택 입력이다. 지난 스프린트에서 이월한 할 일이 있으면 함께 보여준다.
3. **열람실 입장**: 빈자리에 자동 배정되고 랜덤 닉네임을 받는다.
4. **집중**: 할 일을 골라 그 앞에서 집중 타이머를 시작한다. 정해진 길이 없이 시간이 올라가고, 휴식은 휴식 버튼으로 직접 전환한다.
5. **상태 반영**: 집중, 휴식, 완료한 일 수, 남은 일 수가 내 칸에 실시간으로 표시된다.
6. **할 일 완료**: 완료를 체크하면 그 할 일에 쌓인 집중 시간이 실제 소요 시간으로 확정된다. 4번부터 반복한다.
7. **오늘 마무리**: 사용자가 직접 누르면 스프린트가 종료된다. 누르지 않으면 스프린트는 열린 상태로 남아 다음 접속 때 이어진다.
8. **스프린트 회고**: 할 일별 예상 시간과 실제 시간을 비교한다. 예상 시간을 적지 않은 할 일은 비교에서 제외하고 실제 시간만 보여준다.
9. **이월 선택**: 못 끝낸 할 일마다 다음 스프린트로 넘길지, 미완료로 닫을지 고른다.

## 기능 명세

1단계만으로 혼자 쓰는 완결된 서비스가 되도록 하고, 실시간 멀티유저와 회원 기능은 그 뒤에 붙인다.

### 1단계: 혼자 쓰는 가상 열람실 (비회원)

| 기능 | 설명 |
| --- | --- |
| 비회원 식별 | 첫 접속 시 고유 ID를 발급해 브라우저에 저장, 서버 기록과 연결 |
| 스프린트 계획 | 할 일 추가·수정·삭제, 예상 시간 선택 입력, 최소 1개 있어야 입장 |
| 열람실 | 9칸 그리드, 자동 자리 배정, 랜덤 닉네임 |
| 가상 메이트 | 서버가 상태(집중, 휴식, 입장, 퇴장)를 스케줄링해 전송 |
| 집중 타이머 | 할 일별 시작, 스톱워치 방식, 수동 휴식, 선택형 휴식 알림 |
| 집중 기록 | 집중 세션을 할 일에 누적, 완료 시 실제 시간 확정 |
| 오늘 마무리와 회고 | 예상 대비 실제 시간 비교, 미완료 할 일 이월 선택 |
| 투명성 안내 | 가상 메이트가 섞여 있다는 안내 화면 |

### 2단계: 실제 유저와 함께하는 열람실

| 기능 | 설명 |
| --- | --- |
| 실시간 접속 | 실제 유저의 상태를 WebSocket으로 같은 방 사람들에게 전파 |
| 자리 이어받기 | 실제 유저 입장 시 가상 유저를 자연스럽게 퇴장시키고 자리 교체 |
| 인원 정책 | 방마다 최소 인원 유지, 실제 유저가 늘수록 가상 유저 감소 |
| 다중 열람실 | 한 방이 차면 새 방을 열어 자동 배정 |

### 3단계: 확장

| 기능 | 설명 |
| --- | --- |
| 회원 가입·로그인 | 비회원 기록을 회원 계정으로 이전 |
| 방 만들기와 초대 | 직접 방을 만들고 초대 링크로 친구 초대, 빈자리는 가상 메이트로 채움 |
| 내 캐릭터 이미지 | 내가 올린 이미지로 내 화면의 모든 칸을 표시, 이미지는 브라우저에만 저장 |
| 스프린트 기록 모아보기 | 지난 스프린트들의 예상 정확도 추이 |
| 저자극 모드 | 애니메이션과 알림 최소화 |

## 화면 구성

1단계는 화면 3개와 모달 2개로 구성하며, 대표 화면은 "밤에 스탠드를 켜고 공부하는 열람실" 컨셉의 열람실 화면이다.

| 화면 | 주요 요소 |
| --- | --- |
| 첫 화면 | 왼쪽 1/3에 서비스 소개와 가상 메이트 안내, 오른쪽에 스프린트 계획(할 일 입력, 예상 시간 선택, 이월된 할 일, 입장 버튼) |
| 열람실 | 화상 스터디(줌) 화면 구성. 상단 타이머, 3×3 캐릭터 그리드, 할 일 목록 패널, 하단 툴바와 오늘 마무리 버튼 |
| 스프린트 회고 | 할 일별 예상·실제 시간 비교, 총 집중 시간, 미완료 할 일 이월 선택 |
| 설정(모달) | 휴식 알림 켜기와 시간, 알림 소리 |
| 안내(모달) | 가상 메이트가 섞여 있다는 설명, 캠이 필요 없다는 설명 |

첫 화면과 계획을 한 화면에 두어 처음 온 사용자도 할 일을 적고 바로 입장할 수 있다. 3단계에서 회원 기능이 생기면 오른쪽 계획 자리에 로그인 패널을 바꿔 끼운다.

### 열람실 칸 표현

- 집중 중이면 책상 스탠드가 켜지고 캐릭터가 필기한다.
- 휴식 중이면 스탠드가 꺼지고 캐릭터가 엎드린다.
- 칸 하단에 랜덤 닉네임, 상태와 경과 시간, 완료한 일 수와 남은 일 수를 표시한다.
- 입장과 퇴장은 상단에 짧은 알림으로 보여준다.
- PC 화면 옆에 작게 띄워도 보이도록, 창 폭이 좁으면 정보를 줄인 컴팩트 모드로 전환한다.

## 기술 스택과 아키텍처

백엔드는 Spring Boot와 MySQL로 직접 구현하고, 프론트엔드는 AI 바이브코딩으로 만들어 REST API와 WebSocket으로만 연결한다.

| 영역 | 선택 | 비고 |
| --- | --- | --- |
| 언어·프레임워크 | Java 21, Spring Boot 4.1 | 직접 구현하는 핵심 영역. 3.x는 2026년 6월 OSS 지원 종료로 4.1 선택 |
| 실시간 통신 | Spring WebSocket + STOMP | 방 단위 구독으로 상태 전파 |
| 데이터 접근 | Spring Data JPA | 통계 집계는 필요 시 직접 SQL 작성 |
| DB | MySQL (Oracle HeatWave 무료 티어) |  |
| 프론트엔드 | React + Vite + TypeScript, AI 바이브코딩 | 같은 저장소의 `frontend/`, 백엔드와 API로만 연결 |
| 배포 | Oracle Cloud Always Free, Ampere A1 인스턴스 | ARM 기반 |
| API 문서 | Swagger (springdoc-openapi) | 프론트 생성의 기준 |

가상 메이트도 실제 유저와 같은 형식의 이벤트로 WebSocket에 실리기 때문에, 프론트는 둘을 구분하지 않고 그리기만 한다.

프론트를 AI에 맡기는 만큼 API 명세를 먼저 확정하고, Swagger 문서를 기준으로 프론트를 생성한다. 그래야 백엔드 설계가 프론트 코드에 끌려가지 않는다.

## 데이터 모델 초안

1단계 핵심 관계는 비회원 1 : N 스프린트 1 : N 할 일 1 : N 집중 세션이며, 할 일의 실제 시간은 집중 세션의 합으로 계산한다.

| 테이블 | 주요 컬럼 | 설명 |
| --- | --- | --- |
| guest | id(UUID), created\_at, last\_seen\_at | 비회원 식별, 3단계에서 회원과 연결 |
| guest\_setting | guest\_id, break\_alert\_enabled, break\_alert\_minutes | 휴식 알림 기본 꺼짐, 50분 |
| sprint | id, guest\_id, status(OPEN, CLOSED), started\_at, closed\_at | guest당 OPEN 스프린트는 최대 1개 |
| task | id, sprint\_id, title, estimated\_minutes(NULL 허용), status(TODO, DONE, CARRIED, DROPPED), carried\_from\_task\_id, completed\_at | 이월 시 새 스프린트에 새 행을 만들고 원래 할 일을 참조 |
| focus\_session | id, task\_id, started\_at, ended\_at, duration\_seconds, end\_reason | 타이머 한 번이 한 행 |

### 설계 메모

- **이월을 새 행으로 처리**: 원래 할 일의 상태는 CARRIED로 남기고 새 스프린트에 복사한다. 지난 스프린트 회고 기록이 바뀌지 않는다.
- **실제 시간은 저장하지 않고 계산**: 집중 세션을 합산해 구한다. 회고 화면 조회가 느려지면 그때 집계 컬럼을 추가한다.
- **열람실 상태는 DB에 두지 않음**: 자리, 랜덤 닉네임, 가상 메이트의 현재 상태는 자주 바뀌고 영구 보관할 필요가 없어 1단계에서는 서버 메모리에서 관리한다. 2단계에서 서버가 여러 대가 되면 Redis로 옮기는 것을 검토한다.

## 백엔드 핵심 과제

이 프로젝트에서 면접 때 설명할 설계 판단은 아래 여섯 가지이며, 각각 문제와 해결 과정을 기록으로 남긴다.

| 과제 | 단계 | 내용 |

## 리스크와 고려사항

가장 큰 리스크는 기능 범위가 계속 늘어나 1단계 완성이 늦어지는 것이며, 그 외 항목은 아래와 같이 대응한다.

| 리스크 | 대응 |
| --- | --- |
| 범위 확대로 완성 지연 | 단계별 통과 기준을 지키고, 새 아이디어는 다음 단계 목록에 적어둔다 |
| 사용자가 속았다고 느낌 | 가상 메이트가 섞여 있다는 사실을 소개 화면과 열람실 안내에 공개 |
| 의학적 표현 문제 | "ADHD 치료", "증상 개선" 같은 표현을 쓰지 않고 집중 도구로 소개 |
