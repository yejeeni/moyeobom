## ERD

테이블은 5개이며, 열람실·자리·가상 메이트처럼 자주 바뀌고 보관할 필요 없는 상태는 DB에 두지 않는다. 내부 기본키는 BIGINT 자동 증가, 밖으로 노출되는 게스트 식별자만 UUID를 쓴다.

### 설계 메모

- **열린 스프린트 1개 보장**: MySQL은 조건부 UNIQUE 인덱스가 없어서, OPEN일 때만 값이 차는 생성 컴럼 open\_guest\_id에 UNIQUE를 걸어 DB가 직접 막는다.
- **1분 미만 세션**: 진행 중에는 행이 있고, 종료 시 60초 미만이면 행을 삭제한다.
- **누적 시간**: root\_task\_id가 같은 할 일들의 세션을 합치면 재귀 쿼리 없이 이월 전체의 누적 시간을 구할 수 있다.
- **연결 확인 신호를 매번 저장하지 않음**: 10초마다 오는 신호는 메모리에서만 추적하고, DB의 last\_heartbeat\_at은 1분마다 갱신한다. 서버가 죽었다 살아나면 이 값으로 열린 세션을 닫는다. 최대 1분 오차를 받아들이는 대신 쓰기를 크게 줄인다.

## REST API 명세

기록을 남기는 모든 동작은 REST API로 처리하고, 서버는 처리 결과를 열람실에 WebSocket으로 알린다.

### 공통 규칙

- 기본 경로는 `/api/v1`이다.
- 게스트는 모든 요청에 `X-Guest-Id` 헤더로 public\_id를 보낸다. 없거나 모르는 값이면 401을 돌려준다.
- 시각은 ISO-8601 UTC 문자열, 기간은 초 단위 정수로 주고받는다.
- 오류 응답은 `{"code": "SPRINT_ALREADY_OPEN", "message": "..."}` 형식이다.
- 다른 게스트의 할 일이나 스프린트에 접근하면 존재를 숨기기 위해 404를 돌려준다.
- 닫힌 스프린트의 할 일도 수정할 수 없으므로 404로 다룬다.

### 엔드포인트

| 영역 | 메서드와 경로 | 설명 | 주요 오류 |
| --- | --- | --- | --- |
| 게스트 | `POST /guests` | 게스트 발급, public\_id 반환 |  |
| 게스트 | `GET /guests/me` | 게스트 정보와 열린 스프린트 여부 | 401 |
| 설정 | `GET /guests/me/setting` | 휴식 알림 설정 조회 |  |
| 설정 | `PATCH /guests/me/setting` | 휴식 알림 켜기, 시간 변경 | 400 |
| 스프린트 | `GET /sprints/current` | 열린 스프린트와 할 일 목록, 없으면 `sprint: null` |  |
| 스프린트 | `GET /sprints/carryover` | 마지막으로 닫힌 스프린트에서 이월하기로 한 할 일 |  |
| 스프린트 | `POST /sprints` | 할 일 1개 이상으로 스프린트 시작, 이월 할 일 포함 가능 | 400, 409 |
| 할 일 | `POST /sprints/current/tasks` | 할 일 추가 | 400, 404 |
| 할 일 | `PATCH /tasks/{taskId}` | 제목, 예상 시간, 순서 변경 | 400, 404 |

| 할 일 | `POST /tasks/{taskId}/complete` | 완료 처리, 그 할 일에 집중 중이면 세션 종료. 리프레시 문구 반환 | 409 |

| 집중 | `GET /focus/current` | 진행 중 세션과 경과 시간 |  |
| 열람실 | `POST /rooms/enter` | 열람실 입장, 자리와 닉네임 배정 | 409 |
| 회고 | `GET /sprints/current/review` | 할 일별 예상과 실제 비교, 요약. 끝난 세션만 집계 | 404 |
| 회고 | `POST /sprints/current/close` | 미완료 할 일 이월(`CARRY`)·닫기(`DROP`) 결정과 함께 스프린트 종료. 보내지 않은 할 일은 이월 | 400, 404 |

### 주요 요청과 응답

스프린트 시작. 이월할 할 일은 남은 작업 기준 예상 시간을 다시 받는다.

```json
POST /api/v1/sprints
{
  "tasks": [
    { "title": "알고리즘 3문제", "estimatedMinutes": 90 },
    { "title": "자소서 수정", "estimatedMinutes": null }
  ],
  "carriedTasks": [
    { "fromTaskId": 41, "estimatedMinutes": 30 }
  ]
}
```

회고 조회. 예상 시간이 없는 할 일은 `diffSeconds`가 null이다.

```json
GET /api/v1/sprints/current/review
{
  "sprintId": 12,
  "totalFocusSeconds": 9000,
  "completedCount": 2,
  "estimatedSecondsOfDone": 7200,
  "actualSecondsOfDone": 8400,
  "tasks": [
    { "taskId": 51, "title": "알고리즘 3문제", "status": "DONE",
      "estimatedSeconds": 5400, "actualSeconds": 6600, "diffSeconds": 1200,
      "cumulativeSeconds": 6600 },
    { "taskId": 52, "title": "자소서 수정", "status": "TODO",
      "estimatedSeconds": null, "actualSeconds": 600, "diffSeconds": null,
      "cumulativeSeconds": 600 }
  ]
}
```

### 규칙 메모

- 이월은 한 번만 가능하도록 task.carried\_from\_task\_id에 UNIQUE를 건다. 같은 할 일을 두 스프린트로 넘기는 요청은 409가 된다.
- `POST /sprints/current/close`는 진행 중 세션을 `SPRINT_CLOSED`로 닫고, 열람실에서 퇴장 처리까지 한 트랜잭션 흐름으로 처리한다. 방 정리는 커밋이 끝난 뒤 이벤트로 한다.
- 회고 조회는 데이터를 바꾸지 않는다. 오늘 마무리를 누를 때 집중 중이면 클라이언트가 먼저 `POST /focus/stop`(`STOPPED`)을 보낸 뒤 회고를 조회한다.
- 집중 시작, 완료, 마무리는 열린 스프린트 행을 비관적 락으로 잠가 같은 게스트의 요청이 겹치지 않게 한다.

## WebSocket 명세

WebSocket은 서버가 열람실 변화를 알려주는 단방향 통로로만 쓰고, 클라이언트의 동작은 모두 REST API로 보낸다.

### 연결

- 접속 주소는 `/ws`, 프로토콜은 STOMP이다.
- CONNECT 프레임 헤더에 `X-Guest-Id`를 넣는다. 모르는 게스트면 연결을 거부한다.
- 연결 확인 신호(heart-beat)는 양방향 10초로 설정하고, 30초 동안 신호가 없으면 끊김으로 본다. 심플 브로커가 신호 간격의 3배 동안 아무것도 받지 못하면 연결을 끊는 동작을 그대로 쓴다.
- 끊기면 진행 중인 집중 세션을 마지막 신호 시각으로 `DISCONNECTED` 처리하고, 내 자리는 대기 상태가 된다. 방은 60초 유예 뒤 정리한다.
- 클라이언트의 SEND 프레임은 받지 않는다. 다른 사람의 열람실 토픽은 구독할 수 없다.

### 구독 주소

| 주소 | 받는 사람 | 내용 |
| --- | --- | --- |
| `/topic/rooms/{roomId}` | 열람실의 모든 사람 | 자리 입장, 퇴장, 상태 변화 |
| `/user/queue/room-snapshot` | 나 | 구독 직후 열람실 전체 상태 한 번 |
| `/user/queue/notices` | 나 | 휴식 알림과 리프레시 문구 |

토픽을 먼저 구독한 뒤 스냅샷 큐를 구독한다. 서버는 스냅샷 큐 구독이 브로커에 등록된 다음에 스냅샷을 보내므로 유실되지 않는다.

### 이벤트 형식

모든 이벤트는 같은 봉투에 담긴다. 실제 유저와 가상 메이트의 이벤트는 형식이 같아 클라이언트가 구분할 수 없다.

```json
{ "type": "STATE_CHANGED", "roomId": "r-7f3a", "seatNo": 4,
  "at": "2026-10-05T12:00:00.000Z", "payload": { "state": "BREAK", "since": "2026-10-05T12:00:00.000Z" } }
```

| type | payload | 언제 |
| --- | --- | --- |
| `ROOM_SNAPSHOT` | serverTime, mySeatNo, 9개 자리 전체(닉네임, 캐릭터, 상태, since, 완료 수, 남은 수) | 구독 직후, 재연결 직후 |
| `SEAT_JOINED` | 닉네임, 캐릭터 파츠, 상태, since, 완료 수, 남은 수 | 자리에 누군가 들어올 때 |
| `SEAT_LEFT` | 없음 | 자리가 비었을 때 |
| `STATE_CHANGED` | state(`FOCUS`, `BREAK`, `IDLE`), since | 집중 시작, 휴식, 중단, 완료 |
| `COUNTS_CHANGED` | 완료 수, 남은 수 | 할 일 추가, 완료, 삭제 |
| `BREAK_ALERT` | 리프레시 문구 | 설정 시간만큼 집중했을 때, 나에게만 |
| `ROOM_NOT_FOUND` | 없음 | 스냅샷을 구독했는데 방이 없을 때(서버 재시작 등). 클라이언트는 `POST /rooms/enter`를 다시 부른다 |

### 설계 메모

- **경과 시간은 보내지 않음**: 서버는 상태가 바뀐 시각(since)만 보내고, 화면의 "집중 42분"은 클라이언트가 계산한다. 1초마다 메시지를 보내지 않아도 된다.
- **시계 차이 보정**: 스냅샷의 serverTime과 클라이언트 시각의 차이를 저장해 since를 보정한다.
- **캐릭터 파츠**: `{"hair": 3, "hairColor": 2, "shirt": 5, "skin": 1}`처럼 번호만 보내고, 그림은 클라이언트가 그린다.
- **IDLE**: 실제 유저가 할 일을 고르는 대기 상태다. 가상 메이트는 IDLE이 되지 않는다.

## 가상 메이트 동작 설계

열람실과 가상 메이트는 서버 메모리에만 있고, 각 메이트는 "다음 상태가 바뀔 시각"에 한 번 실행되는 예약 작업으로 움직인다.

### 메모리 구조

| 객체 | 가진 것 | 비고 |
| --- | --- | --- |
| RoomRegistry | roomId별 Room, guestId별 roomId | ConcurrentHashMap |
| Room | roomId, 주인 guestId, 자리 9개, 상태(ACTIVE, GRACE), 방 단위 락 | 1단계는 게스트 1명당 방 1개 |
| Seat | 자리 번호, 점유자 또는 빈자리 |  |
| Occupant | 닉네임, 캐릭터 파츠, 상태, since, 완료 수, 남은 수, 종류(REAL, VIRTUAL) | 종류는 서버 안에서만 쓰고 이벤트에는 넣지 않는다 |
| VirtualMate | Occupant + 다음 전이 예약 작업 핸들 | 방이 정리될 때 예약을 취소한다 |

### 행동 규칙

| 항목 | 초기값 |
| --- | --- |
| 집중 지속 시간 | 25\~90분 균등 무작위 |
| 휴식 지속 시간 | 5\~15분 균등 무작위 |
| 집중이 끝날 때 완료 수 증가 확률 | 40% |
| 휴식이 끝날 때 퇴장 확률 | 20% |
| 빈자리가 다시 채워지기까지 | 30초\~2분 무작위 |
| 처음 앉아 있는 메이트 수 | 4\~8명 무작위(나 포함 5\~9명) |
| 처음 빈 자리가 채워지기까지 | 1\~15분 무작위, 자리마다 따로 |
| 과반 집중 규칙 | 휴식에 들어가면 집중 인원이 자리에 앉은 사람(나 포함)의 과반보다 적어질 때, 휴식 대신 집중을 5\~10분 연장. 9명이면 5명, 5명이면 3명 |

모든 값은 `application.yml`의 설정으로 빼서 코드 수정 없이 조정한다.

### 스케줄링 방식

- **매초 확인하지 않음**: 상태가 바뀔 때 다음 전이 시각을 계산해 `TaskScheduler.schedule()`로 한 번만 예약한다. 메이트 수가 늘어도 CPU를 거의 쓰지 않는다.
- **전이 처리 순서**: 방 락을 잡는다 → 규칙에 따라 다음 상태를 정한다 → 이벤트를 발행한다 → 다음 전이를 예약한다 → 락을 푼다.
- **동시성**: 스케줄러 스레드와 사용자 요청 스레드가 같은 방을 바꿀 수 있어서, 방 단위 락으로 순서를 보장한다.
- **테스트 가능성**: 현재 시각은 `Clock`, 무작위 값은 시드를 줄 수 있는 `RandomGenerator`로 주입받는다. 테스트에서 시간을 앞으로 돌려 전이 결과를 확인할 수 있다.

### 처음 입장할 때

방을 만들 때 메이트 4~8명을 무작위 자리에 "이미 공부하던 중"인 상태로 앉힌다. 80%는 집중, 20%는 휴식 상태로 시작하되, 아직 대기 중인 나까지 포함해 과반이 집중하도록 집중 인원을 맞춘다. since를 현재보다 무작위로 앞선 시각으로 정해 "집중 37분"처럼 경과 시간이 제각각 보이게 한다. 완료 수는 0\~3, 남은 수는 1\~4에서 정한다.

### 열람실 생명주기

1. **생성**: `POST /rooms/enter`에서 만든다. 이미 방이 있으면 그 방을 돌려준다. 만든 직후에는 유예 상태로 두어, 60초 안에 WebSocket이 연결되지 않으면 정리한다.
2. **활성**: WebSocket이 연결되면 활성 상태가 된다. 메이트는 방이 정리될 때까지 예약대로 움직인다.
3. **유예**: 연결이 끊기면 진행 중 세션은 바로 닫고, 방은 60초 동안 GRACE 상태로 유지한다. 그 안에 다시 연결되면 같은 방, 같은 닉네임으로 스냅샷을 받는다.
4. **정리**: 유예 시간이 지나거나 회고를 확정하면 모든 예약을 취소하고 방을 지운다. 다음 입장 때는 새 방과 새 닉네임을 받는다.

서버가 재시작되면 방은 모두 사라진다. 클라이언트는 재연결 후 방이 없다는 응답을 받으면 다시 입장한다. 2단계에서 여러 사용자가 한 방을 쓰게 되면 이 메모리 구조를 Redis로 옮기는 것을 검토한다.

## 캐릭터 이미지

캐릭터는 상태별 그림 2장을 번갈아 보여 주는 플립북 방식이며, 그림은 모두 브라우저에서 처리하고 서버는 관여하지 않는다.

### 그림 규칙

| 파일 | 내용 |
| --- | --- |
| `focus-a.png`, `focus-b.png` | 집중. 빠르게 번갈아 바뀐다(빠르기는 캐릭터마다 타자/필기 중 선택) |
| `break-a.png`, `break-b.png` | 휴식. 숨 쉬듯 느리게 바뀐다 |
| `idle-a.png`, `idle-b.png` | 대기. 그 사이 빠르기 |
| `background.png` (선택) | 책상까지 포함한 칸 전체 배경. 상태와 상관없이 한 장 |

- 모두 800x600(4:3) 같은 캔버스 기준으로 그린다. 가이드는 `frontend/public/characters/template.png`.
- 빠진 그림은 대신한다: B가 없으면 A만(움직이지 않음), 그 상태 그림이 없으면 집중 → 대기 → 휴식 순서로 있는 그림.
- 배경이 있는 캐릭터는 배경과 캐릭터를 같은 칸 크기로 겹쳐 위치를 맞추고, 스탠드 효과는 칸 밝기로만 표현한다. 배경이 없으면 기본 배경(또는 코드로 그린 방) 위에 캐릭터를 올린다.

### 저장과 배정

| 항목 | 결정 |
| --- | --- |
| 등록 | 폴더째 가져오기. 상위 폴더를 고르면 안의 캐릭터 폴더들을 한꺼번에 가져온다. 캐릭터 이름은 폴더 이름이고, 같은 이름을 다시 가져오면 바꾼다. 장당 3MB까지 |
| 저장 위치 | 브라우저 IndexedDB. 서버로 보내지 않고 다른 사람에게 보이지 않는다. 브라우저 데이터를 지우면 사라진다 |
| 후보 | 내 캐릭터가 없으면 기본 캐릭터. 있으면 기본 캐릭터를 함께 쓸지 고른다(기본: 함께 씀) |
| 배정 | 자리 주인(자리 번호 + 닉네임)마다 무작위로 뽑고 방 ID별로 브라우저에 기억해, 새로고침이나 재연결 뒤에도 같은 모습이다. 새 메이트가 들어오면 그 자리만 뽑고, 방이 바뀌면 모두 새로 뽑는다 |
| 중복 | 허용 여부를 고른다(기본: 비허용). 비허용인데 후보가 모자라면 안 쓴 기본 캐릭터로, 그래도 모자라면 겹쳐서 채운다 |
| 내 자리 | 무작위가 기본이고, 원하면 특정 캐릭터로 고정한다 |
| 다시 뽑기 | 캐릭터를 가져오면 지금 열람실 배정을 새로 뽑는다. 설정 화면의 '지금 다시 뽑기'로도 새로 뽑을 수 있다 |
| 진입점 | 첫 화면 상단 '내 캐릭터', 열람실 툴바 '캐릭터'(좁은 창에서는 설정 안의 '내 캐릭터') |

서버가 보내는 캐릭터 파츠 번호(`character`)는 그대로 두고, 애니메이션 박자를 자리마다 어긋나게 하는 데와 소개 화면 미리보기에만 쓴다.

## 구현하며 정한 것

문서에 없던 세부 동작은 아래처럼 정했다.

| 항목 | 결정 |
| --- | --- |
| 휴식·대기 상태 저장 | 집중 세션만 DB에 남기고, 휴식·대기와 그 시각은 서버 메모리에 둔다. 서버가 재시작되면 대기 상태로 돌아간다 |
| 끊긴 세션 정리 | 연결된 게스트의 진행 중 세션은 1분마다 `last_heartbeat_at`을 갱신한다. 3분 넘게 갱신되지 않은 세션(연결 없이 REST로만 시작한 경우 등)은 1분마다 찾아 마지막 신호 시각으로 닫는다. 서버가 뜰 때는 열려 있던 세션을 모두 닫는다 |
| 같은 할 일 다시 집중 | 이미 그 할 일에 집중 중이면 새 세션을 만들지 않고 진행 중 세션을 돌려준다 |
| 휴식 알림 | 집중을 시작할 때 한 번 예약하고, 집중이 끝나면 취소한다. 알릴 때 그 세션이 아직 진행 중인지 다시 확인한다. 설정을 바꾸면 다음 집중부터 적용된다 |
| 메이트 초기 인원 | 처음 인원도 무작위로 정해 방마다 분위기가 다르게 보이게 한다. 남은 빈자리는 자리마다 다른 시각에 새 메이트가 들어와 "○○님이 들어왔어요"가 자연스럽게 생긴다 |
| 과반 기준 | 고정 인원(5명) 대신 앉은 사람의 과반으로 계산한다. 인원이 적은 방에서 기준을 채우지 못해 메이트가 계속 쉬지 못하는 문제를 막는다 |
| 메이트 남은 일 수 | 완료 수가 늘 때 남은 수를 1 줄이고, 남은 일이 없으면 1~4개를 새로 적은 것으로 본다 |
| 시각 저장 | DB에는 UTC 기준 `DATETIME(3)`, API와 이벤트에는 ISO-8601 UTC로 내보낸다 |
| 스케줄러 | 메이트 전이, 방 유예, 휴식 알림, 세션 정리, STOMP 연결 확인 신호를 스레드 4개짜리 스케줄러 하나로 돌린다 |
| 동시 입장 | 같은 게스트의 입장 요청이 겹쳐도 방은 하나만 만든다 |

## 개발 규칙과 환경

패키지는 기능별로 나누고, GitHub Flow로 기능마다 PR을 남기며, PR마다 GitHub Actions가 테스트를 돌린다. 배포 자동화는 1단계 기능이 모인 뒤에 붙인다.

### 패키지 구조

```
com.moyeobom
├── guest      게스트 발급, 설정
├── sprint     스프린트, 회고, 이월
├── task       할 일
├── focus      집중 세션, 연결 끊김 처리
├── room       열람실, 자리, WebSocket 이벤트 발행 (websocket: STOMP 인증·연결 추적)
├── mate       가상 메이트 생성과 스케줄링
└── common     설정, 오류 처리, 시간(Clock), 게스트 인증 인터셉터
```

각 기능 패키지 안은 `controller`, `service`, `domain`, `repository`, `dto`로 나누고, 기능 전용 설정값은 `config`에 둔다. 다른 기능의 repository를 직접 부르지 않고 service를 통해서만 접근한다. 다른 기능이 조회만 할 때는 `SprintQueryService`, `TaskQueryService`, `FocusQueryService` 같은 조회 전용 서비스를 쓴다.

기능끼리 상태 변화를 알릴 때는 스프링 이벤트(`MyStateChangedEvent`, `TaskCountsChangedEvent`, `SprintClosedEvent`)를 발행하고, 열람실과 휴식 알림은 커밋 뒤(`@TransactionalEventListener`)에 받는다. 롤백된 변경은 열람실에 보이지 않는다.

프론트엔드는 같은 저장소의 `frontend/`에 둔다(React + Vite + TypeScript).

### 코드 규칙

- 요청·응답 DTO는 Java record로 만든다.
- 엔티티에 setter를 두지 않고, 상태 변경은 `complete()`, `close()`처럼 이름 있는 메서드로 한다.
- 트랜잭션은 service 계층에서만 연다.
- 현재 시각은 `LocalDateTime.now()`를 직접 쓰지 않고 주입받은 `Clock`으로 구한다.

### 예외 처리

오류는 `ErrorCode` enum 한 곳에서 관리하고, `BusinessException`을 던지면 `@RestControllerAdvice`가 공통 형식으로 바꿔 응답한다. 입력값 검증 실패는 어느 필드가 틀렸는지 함께 돌려준다.

| ErrorCode | HTTP | 상황 |
| --- | --- | --- |
| GUEST\_NOT\_FOUND | 401 | X-Guest-Id가 없거나 모르는 값 |
| INVALID\_INPUT | 400 | 제목 공백, 예상 시간 0 이하 등 |
| SPRINT\_ALREADY\_OPEN | 409 | 열린 스프린트가 있는데 새로 시작 |
| SPRINT\_NOT\_FOUND | 404 | 열린 스프린트가 없는데 할 일 추가, 회고 조회 |
| TASK\_NOT\_FOUND | 404 | 없거나 다른 게스트의 할 일 |
| TASK\_HAS\_RECORDS | 409 | 집중 기록이 있는 할 일 삭제 |
| TASK\_ALREADY\_CARRIED | 409 | 이미 이월한 할 일을 다시 이월 |
| NO\_TASK\_FOR\_ROOM | 409 | 할 일 없이 열람실 입장 |
| FOCUS\_NOT\_RUNNING | 404 | 진행 중 세션이 없는데 중단 |
| TASK\_ALREADY\_DONE | 409 | 완료한 할 일에 집중 시작 또는 다시 완료 |
| INTERNAL\_ERROR | 500 | 처리하지 못한 예외. 로그를 남긴다 |

### Git 규칙

- **브랜치**: main과 기능 브랜치만 쓴다. 이름은 `feat/12-task-complete`처럼 이슈 번호와 짧은 설명으로 한다.
- **작업 단위**: 기능마다 GitHub 이슈를 만들고, 브랜치 → PR → 셀프 리뷰 → Squash 병합 순서로 진행한다.
- **커밋 메시지**: 타입은 영어, 내용은 한글로 쓴다. 예: `feat: 할 일 완료 API 추가`

| 타입 | 쓰는 때 |
| --- | --- |
| feat | 기능 추가 |
| fix | 버그 수정 |
| refactor | 동작 변화 없는 구조 개선 |
| test | 테스트 추가·수정 |
| docs | 문서 |
| chore | 설정, 의존성 등 기타 |
| ci | GitHub Actions 설정 |

### 개발 환경

| 항목 | 선택 |
| --- | --- |
| 언어·빌드 | Java 21, Spring Boot 4.1, Gradle. 3.x는 2026년 6월 OSS 지원이 끝나 4.1을 쓴다 |
| 프론트엔드 | React + Vite + TypeScript, Node 22. 개발 서버(5173)가 `/api`, `/ws`를 백엔드로 프록시 |
| 스키마 | Flyway 마이그레이션으로 관리하고, JPA는 `ddl-auto: validate`로 검증만 한다(생성 컬럼 등 DDL을 직접 쓰기 위해) |
| 로컬 DB | Docker Compose로 MySQL 8.4 실행. 운영 HeatWave 버전과 맞는지 배포 전에 확인. 3306이 사용 중이면 `.env`의 `DB_PORT`를 바꾼다 |
| 프로필 | local, test, prod로 나눈다. local에서만 기능 확인용 `/dev.html`을 연다 |
| 비밀 정보 | DB 비밀번호 등은 환경 변수로 받고, `.env`는 Git에 올리지 않는다 |
| CI | PR을 올리면 GitHub Actions가 백엔드 빌드·테스트(`build`)와 프론트엔드 린트·빌드(`frontend`)를 실행하고, 실패하면 병합하지 않는다 |
| 배포 | 1단계 기능이 모인 뒤 GitHub Actions 자동 배포를 추가한다 |
